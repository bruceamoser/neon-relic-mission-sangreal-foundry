# Agent operation: one asset at a time

Read `art/README.md`, the selected manifest entry, its source excerpt and current source resolutions. The production user request is preserved in `art/spec/production-request.md`. Creative requirements come from the canonical art specification; operation and approval scope come from the user's request.

1. Run `validate`, then `refresh`. For a batch, enumerate READY IDs for the requested Act; do not combine them into one prompt or canvas.
2. For a single asset, inspect reference requirements and checkpoints. Produce prerequisites only within the user's authorized scope. Blocked canonical values require an actual user answer, never an invented number or history.
3. Run `begin ID` (or targeted `--operation edit`). This reserves exactly one attempt and persists the prompt, reference hashes and timestamp before generation. Read the returned attempt prompt verbatim.
4. Use the imagegen skill and built-in image_gen. View every local reference/edit target before using it. Supply locked reference paths as image references; identify an edit target separately. Make exactly one tool call for this one asset; never combine multiple jobs, even when parallel agents are working. If reference capacity is insufficient, stop and record the limitation rather than silently dropping a locked identity.
5. Return the tool's generated image as prescribed by its tool interface and preserve its returned local file using `ingest`. Do not claim that a tool success is an approved image. If no usable local output is returned, record a recoverable failure; do not silently switch to an API/CLI service.
6. View the actual image at useful resolution and inspect the small clues. Check every mandatory Egg plus identity, props, period, medium, composition, dimensions, anatomy, faces, hands, duplicates, symbols, geometry, text and numbers. Write observed evidence, reviewer and timestamp into the generated QA YAML. A prompt is not inspection evidence. FAIL or AMBIGUOUS must not be promoted to PASS because the prompt requested the feature.
7. Record QA. Prefer NEEDS_EDIT for one or two correctable defects; use NEEDS_REGENERATION for fundamentally wrong composition, identity, medium, excessive artifacts or a multi-panel output. Keep all rejected work. For edits, preserve unrelated content and recheck the entire resulting image. Stop repeated unsuccessful attempts and record BLOCKED with the failed requirement and a recommended manual intervention.
8. For exact wording, inspect the underlying surface and composite separately. Match perspective, type, ink, grain and blur. Do not invent surrounding document prose. For complex geometry use an external compositor and the provenance import path. A recurring prop reference's typography is not proof that the generated scene rendered it correctly.
9. Perform the second, final visual QA on the actual composite or final no-text image. Every mandatory criterion, including every exact string, must PASS. Then approve to write the canonical WebP and lock its hash. Approved files are immutable unless the user explicitly requests a separately tracked revision.
10. Present human review at the six requested batch checkpoints, not after every image. Only record a checkpoint from an actual approval. Bulk production is gated on calibration and locked character/prop sets; remaining Acts additionally require the first completed Act checkpoint.
11. Prepare approved-only Foundry integration after the requested review stage. Review card drafts for player/DA separation, NPC mappings, N02's extra-detail placement and board/web links. Ask for final integration approval only when the concrete staged plan is ready. Then apply and run repository build/validate/audit. Do not infer a deployment destination.

Keep `art/art-manifest.yaml`, `art/qa/`, and `art/work/history/` authoritative; never rely on chat history as the only production record. Use CLI commands to coordinate the shared manifest safely. A queued job or a synthetic test is never a generated production asset.
